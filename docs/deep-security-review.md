日期：2026-10-14。范围：本地 `MTP一键部署.sh` 全部管理命令、README、两份既有审查/验收文档及自动化测试。目录没有 Git 元数据；审查阶段没有访问远程、下载任何软件/源码或操作真实 VPS。后续 GitHub 发布属于另行授权的步骤。当前代理引擎提交、Fake TLS、协议参数和 systemd 部署方式保持不变，未新增 Docker 依赖。

P1（已修复）：

| 问题 | 证据与后果 | 修复 |
| --- | --- | --- |
| 卸载确认后的校验窗口 | 模拟在等待 YES 时添加用户数据，旧版继续删除整个目录 | 确认后、停止服务后再次检查归属、账号及文件白名单 |

| 原子替换后的 TERM 窗口 | mv 成功但 replaced 尚未赋值时发送 TERM，旧配置丢失 | 结合替换尝试、备份完成及临时文件存在性判断回滚；测试退出 143 且旧数据恢复 |
| 统计端口自检误报 | 绑定具体公网 IPv4/IPv6 或混合监听时原自检返回 0 | 逐条核验回环地址和本服务 PID；公网绑定返回失败 |
| 卸载目录内特殊资源漏检 | 空目录可冒充轮转日志；硬链接与嵌套挂载未被拒绝 | 白名单同时检查常规文件/单硬链接；读取 mountinfo 拒绝专属路径及其内部挂载 |
| 卸载重载失败留下不可自动重试的目录 | 原流程先删 unit，再 daemon-reload；失败阻断目录删除 | 先完成已核验文件清理，再重载；失败明确告知 systemd 缓存需人工处理 |

P2（已修复或加固）：

- `wc -l` 漏检未换行的末尾未知字段；Bash 丢弃 NUL 后可能接受原始非法数据。改为有大小/字节约束的逐行六字段解析，拒绝重复、未知、空行、无效值和控制字符；保留空 TAG 与合法末行无换行。
- `fetch` 在条件调用上下文中可能忽略 curl 的失败，并把非空的部分下载当成功；显式传播下载失败，限制重定向为 HTTPS。
- 配置只有包含 `proxy_for` 就被视为有效。新增大小、控制字符、明显 HTML、指令基本格式与端口检查；同内容更新跳过重启，下载结束再次检查停止状态。回滚后也核验旧服务监听。
- `self-test` 没有检查刷新 timer 活动与自启状态，现纳入异常返回码。
- 锁采用不截断的打开方式，拒绝符号链接、硬链接和不安全权限；保留锁文件，防止 unlink 后不同进程锁住不同 inode。
- 构建临时目录固定放在受检查的 `/tmp`，不信任继承的 TMPDIR；校验随机 Secret 输出格式。systemd drop-in 查询和账号枚举失败时拒绝继续。
- 修正旧卸载取消测试：此前可能在账号检查处提前失败，未真正测试确认；现在确认实际到达取消分支。测试中的 stat/hardlink 适配避免依赖 macOS 专有参数。

## 2. 修复记录与设计边界

安装与 refresh 使用各自子 Shell 的 EXIT/INT/TERM trap，保持原失败码，临时文件使用随机名字。安装从下载、校验、编译完成后才创建账号和服务；清理按本次创建的资源身份进行，文件未写完也可识别。资源被替换、出现无关文件/挂载、账号被共用、无法确认身份或删除失败时，优先保留残留并报错。

卸载仍要求大写 YES，且只针对专属目录、三个 unit、轮转配置及独立账号。日志仅接受常规单链接文件和精确的轮转文件名。缺失文件的部分安装不会被新版卸载强行接管。配置/日志是可变资源，不进入静态摘要；其类型和权限仍需满足检查。静态文件被管理员合法修改也会触发拒绝，这是保守的归属边界。旧安装缺少 account/manifest 时不得直接覆盖新版管理器或伪造记录。

刷新流程为 HTTPS 下载 → 基本格式检查 → 同内容比较 → 再确认活动状态 → 保存旧数据 → 同目录原子替换 → 重启并确认监听。下载/校验/替换失败不会主动重启；成功替换后的启动失败或可捕获信号尝试恢复旧配置。真正发生变更时仍会中断现有连接，无法承诺零停机。校验器没有取代引擎完整解析器，也没有证明代理上游可达。

锁文件保留不代表锁仍被占用；进程退出时 flock 释放，/run 在重启时重新建立。不要用删除锁文件解决并发问题。本轮只模拟 flock 边界，没有实际 Linux 并发压力测试。

## 4. 实际测试

环境：macOS arm64、Bash 3.2.57、Python 3.9.6。执行：

```bash
bash -n MTP一键部署.sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

结果：Bash 语法检查通过；共 60 个测试方法，59 通过，1 跳过。子测试覆盖多个故障/地址/配置案例，方法数不等于真实 VPS 场景数量。跳过项是 ShellCheck：本机没有该工具，遵守禁止下载要求，未执行 lint，不声称 lint 通过。

覆盖：

- 安装下载/网络中断、编译、useradd、daemon-reload、enable、启动确认（8443 和 443）、timer 启动、标记写入、部分 unit 写入、TERM；检查专属路径与临时目录清理。账号删除失败或组共用时保留资源。
- 配置空行/空字段/重复/未知末行/超长/特殊字符/NUL/非法 Secret，以及有效配置无末尾换行；不执行配置中的命令。
- 卸载确认、确认期间新增数据、符号链接、硬链接、文件类型、修改 unit、替换目录、部分安装和重载失败；挂载检查使用人工构造 mountinfo 样本。
- 刷新下载失败、停止状态、下载期间停止、坏数据、相同数据、rename 失败、重启失败回滚、原子替换后 TERM 恢复旧配置。
- TCP IPv4/IPv6、host mode 与 systemd socket 监听样本；Docker IPv4/IPv6 bridge 单端口/范围及 UDP 区分；统计回环与公网混合监听。
- 完整模拟安装生成 systemd/logrotate 文件，核对用户、权限限制、低端口能力、恢复与自启配置；健康/异常 self-test 和返回码。

系统调用使用测试替身：下载、编译、systemd、账号创建/删除和 chown 不操作主机；元数据检查以真实临时文件字节、inode、硬链接/权限位及模拟 root/mtp 身份运行。所有临时文件在 TemporaryDirectory 或脚本 trap 中清理。没有运行真实引擎；配置样本和监听样本是测试输入，不能作为真实 Telegram/Linux 输出证明。

## 5. 未验证风险

| 未执行项目 | 限制与验收要求 |
| --- | --- |
| Ubuntu 22.04 / 24.04、Debian 12 原生流程 | 本机非 Linux；GNU stat、sed、getent、useradd/groupadd 和 kernel mountinfo 需逐发行版验收 |
| systemd-analyze verify、真实崩溃/临时断网/重启恢复 | 没有 systemd；生成文件检查不是 systemd 执行测试。按 VPS 清单强制结束仅本项目 PID、断开测试网络并重启 |
| 真实 logrotate、日志增长上限 | 没有 logrotate；copytruncate 有少量日志丢失窗口，maxsize 依赖调度而非硬上限。持续崩溃无限重试仍会产生日志 |
| 实际 Nginx/Caddy/宝塔/Docker 共存 | 只有端口/映射样本测试；其他 daemon/rootless、手工 NAT、跨命名空间和检查后的端口抢占需真实确认 |
| Telegram 配置当前格式、Fake TLS 握手和上游连接 | 禁止下载，未取回当前官方数据或引擎源文件；基本校验可能在上游语法改变时保守拒绝，不应随意放宽，先核验原始响应及引擎兼容性 |
| DNS、TLS/CA 和源码供应链 | 引擎源码固定提交及 SHA256、下载保持 TLS 校验且不允许 HTTP；本轮未在线重新核验归档摘要。README 的安装脚本 main 地址仍可变，须审阅并保存可信脚本版本；引擎摘要不能验证安装脚本本身，也不证明原引擎不存在漏洞。官方动态数据仍信任 TLS/CA |
| 长期资源和故障恢复 | 没有流量、长期 CPU/内存/磁盘样本；5 秒无限重试可恢复短暂失败，也会持续重试永久错误，应监控并修正根因 |
| SIGKILL、断电、文件系统错误及其他 root 操作 | trap 无法保证全部回滚；创建资源与记录身份之间仍存在不可消除的中断窗口。管理员绕过锁同时修改文件/账号不能获得绝对并发安全保证，异常时人工核验 |

Secret 仍可能从引擎命令行被有进程查看权限的本地账号读取。权限/静态摘要不能抵御已有 root 权限的攻击者，不适合作为多租户隔离保证。脚本不修改其他服务、网络或防火墙；云安全组及入站/出站策略仍需人工确认。
