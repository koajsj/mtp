# 生产审查与验证记录

日期：2026-10-14。范围：当前本地项目全部源码、README、测试及验收文档。本地目录没有 Git 元数据；本轮未访问远程仓库、下载软件/引擎、操作真实 VPS 或发布修改。保留原引擎提交、协议逻辑、独立 mtp 账号、systemd 和既有端口保护理念。

## 审查结果

P0：本次源码审查未确认无需额外权限即可破坏其他服务或取得 root 的 P0 问题。此结论不是完整渗透测试或生产安全保证。

P1（已修复）：

- 原归档路径校验 awk 表达式语法错误，阻断安装。完整模拟安装复现后修正，仍保留归档 SHA256 校验。
- `ProtectSystem=strict` 将日志目录设为只读，而启动命令要重定向写日志，服务可能无法启动。增加仅针对 `/var/log/mtp` 的 `ReadWritePaths`。
- 原日志轮转使用 mtp 身份，但日志目录为 root 所有且 mtp 不可写，轮转失败会导致持续增长。改为 root 轮转，每日/超过 10 MiB 调度时轮转，要求已有 logrotate。
- `RETURN` trap 无法覆盖脚本异常退出，且原 ERR 清理未覆盖全部安装阶段。安装和刷新使用子 Shell 的 EXIT/INT/TERM 清理；失败时保留错误码。刷新替换失败后恢复备份，恢复失败保留备份。
- 定时刷新会启动用户主动停止的服务，卸载也未停止刷新 service。刷新跳过停止状态，管理操作串行加锁，卸载同时停止刷新 unit。
- 卸载仅按同名账号删除，未验证账号身份变化/组共用；文件白名单接受带用户数据后缀的文件、符号链接及换行文件名。新增 root 所有的 UID/GID 归属记录，拒绝不同账号、其他组成员、未知文件/符号链接；检查实际 unit 加载路径和 drop-in。账号删除失败先保留文件，以便重试。
- Docker 端口范围可能漏检，UDP 映射会误报 TCP 冲突。按 TCP 协议及宿主端口范围检查，保留既有容器。

P2（已修复）：

- 超长端口数字会在 Bash 算术中溢出，现限制为最多 5 位数字并检查范围；加载配置也约束统计端口不得低于 1024。
- 原 `status` 对停止/失败状态仍返回成功；现返回 systemd 活动状态。安装、启动、重启、刷新核对监听 PID，最多等待 20 秒。
- 关闭 systemd 启动次数限制，允许慢网络/持续启动失败后的自动重试；保留 Restart=always 与 5 秒重试间隔。
- 添加只读 `self-test`：配置/Secret 格式、Telegram 数据文件、目录/配置/日志权限、账号归属、systemd 状态、客户端监听 PID、统计端口绑定、日志轮转配置。
- 固定管理 PATH、设置 umask 027；管理命令拒绝多余参数。修正变量紧邻中文标点的解析边界，并在进入安装子 Shell 前保存脚本路径。

## 实际验证

在 macOS、本机 Bash 3.2.57、Python 3.9 执行：

- `bash -n MTP一键部署.sh`：通过。
- `PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v`：34 项，33 通过、1 跳过。
- 跳过的是 ShellCheck：本机没有该程序，遵守禁止下载要求，不自动安装，不宣称 lint 通过。
- 模拟覆盖 Nginx、Caddy、Apache、宝塔、既有代理的 443 冲突及 Docker TCP 单端口/范围/UDP 区分；参数错误、已存在目录和厂商 unit；安装下载失败清理；停止后刷新；刷新重启失败回滚；卸载取消、账号冲突、未知文件/符号链接；配置不执行；正常/异常自检；其他进程监听不能视为本服务成功。
- 完整模拟安装真实生成目录和配置文件，但替换了下载、编译、账号管理、权限/服务命令。Linux stat 和 GNU sed 的行为在相关测试中模拟；不代表原生 Linux 工具或真实 systemd 校验通过。

| Telegram 外部握手与长期 CPU/内存/磁盘表现 | 未连接真实代理，无流量或长期样本；需外部客户端和实际监控 |

源码使用 GNU stat/sed、Bash 数组、flock、getent/useradd/groupadd 及常规 systemd 配置；目标发行版的兼容性仅经过静态审查，尚未通过实际发行版验收。network-online 的等待效果依赖网络管理器；日志 maxsize 取决于系统调度，不能保证日志始终小于 10 MiB。当前 Docker 检测无法覆盖其他 daemon/rootless 实例或手工 NAT，需人工检查。

Secret 仍可能由有进程查看权限的本地账号从代理引擎参数读取。保持当前引擎和协议不变，推荐只有可信账号的个人 VPS。旧安装缺少账号归属记录时，新版卸载保守拒绝；不能自动推断资源来源。

SIGKILL、断电或磁盘/文件系统错误不能由 trap 保证清理；可能留下待人工核验的残留。专属目录内不能存放用户数据。防火墙和云安全组仍由用户管理，本轮没有改动其他服务配置。

这些修复解决了已证实的源码问题，但在完成真实 VPS 验收前，不能宣称已经达到生产运行标准。
